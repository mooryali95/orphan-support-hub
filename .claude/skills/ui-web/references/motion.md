# الحركة

> قِس كل حركة بأربعة أسئلة **بالترتيب**. لا تكتب سطر حركة قبل أن تجيب عنها.

## ١. هل تتحرّك أصلاً؟ (التكرار)
| كم يراها المستخدم | القرار |
|---|---|
| 100+ مرة يومياً (اختصار لوحة مفاتيح، لوحة الأوامر) | لا حركة. أبداً |
| عشرات المرات (تمرير، تنقّل في قائمة) | احذفها أو قلّلها جداً |
| أحياناً (نافذة، درج، إشعار) | حركة قياسية |
| نادراً / أول مرة (ترحيب، إتمام كفالة، احتفال) | يُسمح بلمسة بهجة |

**ما يبدأ من لوحة المفاتيح لا يتحرّك** — يُحسّ بطيئاً ومنفصلاً عن اليد.

## ٢. ما الغرض؟
مقبول فقط: **اتّساق مكاني** (يدخل ويخرج من الجهة نفسها)، **إظهار حالة**، **شرح**، **ردّ فعل** (زرّ ينضغط)،
**منع القفز** (ظهور/اختفاء مفاجئ). «يبدو جميلاً» + يتكرّر كثيراً = لا تحرّك.

## ٣. أيّ منحنى؟
```
دخول/خروج            → ease-out
حركة/تحوّل على الشاشة → ease-in-out
تمرير/تغيّر لون        → ease
حركة دائمة (شريط تقدّم) → linear
الافتراضي              → ease-out
```
**لا `ease-in` في الواجهة** — يؤخّر اللحظة التي تراقبها العين.
المنحنيات المدمجة ضعيفة؛ استعمل رموزاً مخصّصة (تُعرَّف مرة في `:root`):
```css
--ease-out:    cubic-bezier(0.23, 1, 0.32, 1);
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);  /* أدراج بطابع iOS */
```

## ٤. كم تدوم؟
| العنصر | المدّة |
|---|---|
| ضغط زرّ | 100–160ms |
| تلميح، نافذة صغيرة | 125–200ms |
| قائمة منسدلة | 150–250ms |
| نافذة حوار، درج | 200–350ms (حتى 500ms للأدراج الكبيرة بالسحب) |
| شرح/تسويق | أطول بحسب الحاجة |

**القاعدة:** عناصر الواجهة المرتبطة بالمؤشّر تحت 300ms. النوافذ والأدراج استثناءٌ مضبوط بالجدول — لا تناقض.
**الخروج أسرع من الدخول** (مثلاً دخول 250ms، خروج 150ms)؛ النظام يستجيب بسرعة، والمستخدم يقرّر ببطء.

## الإحساس بالسرعة
- مؤشّر تحميل أسرع دوراناً = تحميل يُحَسّ أسرع.
- بعد أول تلميح مفتوح، التالي يظهر فوراً بلا تأخير ولا حركة.
- `ease-out` 200ms يُحَسّ أسرع من `ease-in` 200ms.
- الحركة لا تخفي البطء: أظهر هيكلاً (skeleton) أو نتيجة متفائلة بدل مؤشّر طويل.

## النوابض (springs)
للسحب بزخم، والإيماءات القابلة للقطع، والعناصر «الحيّة». تحفظ السرعة عند المقاطعة بينما الإطارات المفتاحية تبدأ من الصفر.
```js
{ type: "spring", duration: 0.5, bounce: 0.2 }   // أسهل للفهم
{ type: "spring", mass: 1, stiffness: 100, damping: 10 }
```
الارتداد 0.1–0.3 ولا ارتداد في لوحات العمل. ربط قيمة بموضع المؤشّر بنابض فقط حين تكون زخرفية؛ في رسمٍ بياني وظيفي لا حركة.
**المشروع لا يحمل مكتبة حركة** — لا تُضف Motion لحركة يكفيها CSS؛ أضفها فقط للإيماءات والنوابض الحقيقية.

## أدوات CSS
- **انتقالات لا إطارات مفتاحية** لكل ما يُطلق بسرعة (إشعارات، تبديل): الانتقال يُعاد توجيهه من مكانه.
- **`@starting-style`** لحركة الدخول بلا JS، ومعه للعناصر التي تُخفى بـ `display`:
  ```css
  .panel { transition: opacity 200ms var(--ease-out), transform 200ms var(--ease-out),
           display 200ms allow-discrete, overlay 200ms allow-discrete; }
  @starting-style { .panel { opacity: 0; transform: translateY(4px); } }
  ```
  البديل حيث لا يُدعم: سمة `data-mounted` بعد أول رسم.
- **لا `scale(0)`**: ابدأ من `scale(0.95)` + `opacity: 0`.
- **`translateY(100%)`** بالنسبة المئوية (حجم العنصر نفسه) لا بالبكسل.
- **`scale()` يكبّر الأبناء** — ميزة عند ضغط زرّ، وعيب لنصٍّ يجب أن يبقى حادّاً.
- **ضبابية خفيفة** `blur(2px)` تُخفي تقاطع حالتين في التبديل؛ تحت 20px دائماً (مكلفة في Safari).
- **`clip-path: inset()`** للكشف وألسنة التبويب وأشرطة المقارنة — بلا عناصر إضافية.
- **View Transitions** (`document.startViewTransition`) للانتقال بين الصفحات/الحالات الكبيرة، مع بديل فوري.
- **WAAPI** (`el.animate()`) للتحكّم البرمجي بأداء CSS.
- **التتابع (stagger):** 30–80ms بين العناصر، بمتغيّر لا بـ `nth-child` مكرّر، ولا يمنع التفاعل:
  ```tsx
  <li style={{ "--i": i } as React.CSSProperties} className="stagger" />
  /* .stagger { animation: rise 250ms var(--ease-out) both; animation-delay: calc(min(var(--i), 8) * 40ms); } */
  ```
  حدّ أقصى للتأخير (8 عناصر) حتى لا تنتظر القائمة الطويلة ثانية.

## RTL والحركة (ما تغفله المراجع)
- **`translateX` و`clip-path: inset()` فيزيائيان** لا منطقيان: عنصر «يدخل من البداية» يدخل من اليمين في RTL.
  اضرب في اتجاه: `--dir: 1` في LTR و`-1` تحت `[dir=rtl]`، ثم `translateX(calc(var(--dir) * 100%))`. وفي `inset()` بدّل الجانبين.
- **أصل التحويل** في Radix/shadcn: `transform-origin: var(--radix-popover-content-transform-origin)` (وما يقابله لـ dropdown/tooltip/hover-card) — يتبع الاتجاه تلقائياً. النوافذ الحوارية تبقى من المركز.
- **السحب للإغلاق** يتبع الاتجاه: درج البداية يُسحب نحو البداية.
- الإشعارات (sonner) في RTL: `position="top-left"` يعني جهة «النهاية» بصرياً — اختر بحسب الاتجاه لا بالحرف.

## إتاحة الحركة
- `prefers-reduced-motion: reduce` = حركة **أقلّ وألطف**، لا صفر: أبقِ الشفافية واللون، وأزل الإزاحة والتكبير والتتابع.
  ```css
  @media (prefers-reduced-motion: reduce) {
    *, ::before, ::after { animation-duration: .01ms !important; animation-iteration-count: 1 !important;
                            transition-property: opacity, color, background-color !important; scroll-behavior: auto !important; }
  }
  ```
  وتأكّد أن الحالة النهائية **مرئية** (حركة تبدأ من `opacity:0` بـ `both` لا تُترك مخفية).
- الحركة ليست القناة الوحيدة للمعلومة؛ النجاح/الخطأ يُعلن بنصٍّ و`aria-live`.
- لا وميض أكثر من 3 مرات في الثانية.
- التمرير بحركة على أجهزة اللمس: `@media (hover: hover) and (pointer: fine)`.

## فحص الحركة
- أبطئها (لوحة Animations: 10٪ أو ×5 المدّة) وتصفّحها إطاراً إطاراً: تقاطع حالتين؟ أصل خاطئ؟ خصائص غير متزامنة؟
- جرّب الإيماءات على جهاز حقيقي (Safari remote / Chrome remote) لا المحاكي.
- راجعها في اليوم التالي بعين جديدة.
- طابق الشخصية: لوحة إدارة = حادّة وسريعة؛ صفحة الكفيل/الاحتفال = أنعم قليلاً. كل الحركات في السطح بنفَسٍ واحد.
