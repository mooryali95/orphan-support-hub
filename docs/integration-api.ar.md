# واجهة التكامل — للمنصّات الشريكة

> `POST /api/integrations/orphans` — إرسال مستفيديك إلينا.
> `GET  /api/integrations/orphans` — قراءة بطاقات المستفيدين.

## قاعدتان قبل أيّ شيء

**(١) الوارد لا يُنشَر.** كل سجلّ يصل من منصّةٍ شريكة يقف عند
`under_review` مهما قالت حمولتُه، ولا يظهر لأي كافل حتى تعتمده إدارتنا
بعد مراجعة وثائقه. ولا يستطيع المفتاح رفعَ ملفٍّ إلى الاعتماد.

**(٢) القراءة بطاقةٌ لا ملفّ.** تُعيد الواجهة ما يراه الزائر على
موقعنا: اسمٌ مستعار، وبلدٌ ومنطقة، و**فئةٌ عمرية** (لا تاريخ ميلاد)،
وجنسٌ ومرحلة دراسية، وحالُ التمويل. ولا تُعيد قصّةً ولا صورةً ولا
مدينة. مفتاحُ الشريك ليس إذناً برؤية ملفّ طفل — الإذن عندنا يُطلَب
ويُمنح لشخصٍ بعينه ويَنقضي.

## المصادقة

ثلاث ترويسات في كل طلب:

| الترويسة           | القيمة                                |
| ------------------ | ------------------------------------- |
| `X-IOCO-Key`       | مفتاح العميل (`ioco_ck_…`)            |
| `X-IOCO-Secret`    | السرّ (`ioco_sk_…`)                   |
| `X-IOCO-Timestamp` | الوقت الآن، بالثواني أو بالمللي ثانية |

ختمُ الوقت يجب أن يقع داخل **خمس دقائق** من وقتنا، وإلّا رُفض الطلب
(`stale_timestamp`) — وبدون هذه النافذة يُعاد الطلب الملتقَط إلى الأبد.

> **السرّ يُعرض مرّةً واحدة عند الإصدار.** نحفظ تجزيئه بملحٍ لا السرّ
> نفسه، فلا نستطيع إعادة عرضه ولو أردنا — ولو سُرقت قاعدتنا لما مُكِّن
> أحدٌ من انتحالك. ومن فقد سرّه يطلب إصدار غيره وإبطال الأوّل.

وكل مسارات الفشل في المصادقة تُعيد `invalid_credentials` نفسه عمداً:
التمييز بين «مفتاح غير موجود» و«سرّ خاطئ» يُعطي مِسباراً تُعدّ به
المفاتيح الصالحة.

## النطاقات

| النطاق           | يُتيح                     |
| ---------------- | ------------------------- |
| `orphans:read`   | `GET` — قراءة البطاقات    |
| `orphans:import` | `POST` — إرسال المستفيدين |

ونطاق الاستيراد **يحتاج جهة رعاية معتمدة** مسؤولة عن الملفّات الواردة:
ملفٌّ بلا جهةٍ معتمدة لا صاحب له.

## الاستيراد

```http
POST /api/integrations/orphans
X-IOCO-Key: ioco_ck_…
X-IOCO-Secret: ioco_sk_…
X-IOCO-Timestamp: 1790000000
Idempotency-Key: batch-2026-10-24-001
Content-Type: application/json

{
  "records": [
    {
      "external_ref": "YOUR-ID-123",
      "display_name": "محمد . أ",
      "country": "الأردن",
      "region": "إربد",
      "city": "الرمثا",
      "gender": "male",
      "birth_date": "2016-04-12",
      "education_stage": "ابتدائي",
      "monthly_need": 150,
      "currency": "USD",
      "story": "…"
    }
  ]
}
```

- **`external_ref` معرّفك أنت**، ومقصورٌ عليك: شريكان بالمرجع نفسه
  يُنشئان ملفّين مستقلّين، ولا يكتب أحدكما فوق الآخر.
- **`display_name` و`country` إلزاميان** عند الإنشاء. والبلد إلزاميّ
  لأن للعمود قيمةً افتراضية، فلو تُرك لها لظهر مستفيدٌ أردنيّ تحت
  السعودية في الفلترة — وفلترةٌ تكذب أسوأ من فلترةٍ ناقصة.
- **الجهة تُؤخذ من مفتاحك لا من الحمولة.** أي `org_id` في السجلّ
  يُتجاهل.
- أقصى دفعة **١٠٠ سجلّ**.

### التكرار

مرّر `Idempotency-Key`. إعادةُ إرسال الدفعة نفسها بالمفتاح نفسه تُعيد
**النتيجة الأولى** بلا إنشاء ملفّاتٍ مكرّرة (`"replayed": true`).
واستعمالُ المفتاح نفسه لحمولةٍ مختلفة يُرفض بـ`idempotency_key_reused`
— وهو خطأٌ في الاستدعاء يستحقّ أن يُقال لا أن يُبتلع.

### التحديث

إعادةُ الإرسال بالمرجع نفسه تُحدّث السجلّ. وملفٌّ **اعتمدته إدارتنا**
تُقبل تعديلاته الوصفية ويُردّ **`monthly_need`**: كافلٌ التزم بمبلغٍ
على احتياجٍ معلَن، وتغييرُه من الخارج نقلٌ للمرمى بعد التسديد. ويُقال
لك ما رُدّ:

```json
{ "ok": true, "action": "updated", "ignored_fields": ["monthly_need"] }
```

ولتغيير احتياج ملفٍّ معتمَد راسل إدارتنا.

### الردّ

```json
{
  "ok": true,
  "received": 2, "created": 1, "updated": 1, "rejected": 0,
  "results": [ { "ok": true, "action": "created", "status": "under_review", … } ],
  "note_ar": "كل سجلّ مستورَد يقف عند under_review حتى تعتمده الإدارة."
}
```

## القراءة

```http
GET /api/integrations/orphans?country=الأردن&age_band=age_6_11&funding=open&limit=50
```

| المُعامل            | القيم                                                              |
| ------------------- | ------------------------------------------------------------------ |
| `country`, `region` | نصّ                                                                |
| `age_band`          | `under_6` · `age_6_11` · `age_12_14` · `age_15_17` · `age_18_plus` |
| `gender`            | `male` · `female`                                                  |
| `funding`           | `any` · `open` · `full`                                            |
| `limit`, `offset`   | ترقيم؛ الحدّ الأقصى ٦٠                                             |

ويُعاد `total` مع الصفحة — صفحةٌ بلا عددٍ لا يُبنى عليها ترقيم.

## رموز الخطأ

| الرمز                    | الحالة | المعنى                           |
| ------------------------ | ------ | -------------------------------- |
| `missing_credentials`    | 401    | ترويسةٌ ناقصة                    |
| `stale_timestamp`        | 401    | ختم الوقت خارج النافذة           |
| `invalid_credentials`    | 401    | مفتاح أو سرّ غير صالح، أو مُبطَل |
| `scope_denied`           | 403    | المفتاح بلا النطاق المطلوب       |
| `client_not_permitted`   | 403    | العميل غير مخوَّل بالعملية       |
| `invalid_json`           | 400    | الحمولة ليست JSON صالحاً         |
| `records_required`       | 400    | `records` غائبة أو فارغة         |
| `batch_too_large`        | 413    | أكثر من ١٠٠ سجلّ                 |
| `idempotency_key_reused` | 409    | المفتاح نفسه بحمولةٍ مختلفة      |
| `country_required`       | —      | السجلّ بلا بلد                   |
| `display_name_required`  | —      | السجلّ بلا اسم                   |
| `org_not_approved`       | —      | جهة المفتاح غير معتمدة           |

وكل خطأ يحمل `message_ar` و`message_en`.

## الإبطال

يُبطَل المفتاح من لوحة الإدارة، **فيتوقّف فوراً** قراءةً واستيراداً.
والملفّات التي وردت منه تبقى كما هي: الإبطال يُغلق الباب ولا يحذف ما
دخل منه.

---

## ملاحظة على التصميم: لماذا سرٌّ حامل لا HMAC

خارطة الطريق كتبت «توقيع HMAC»، وهو الصواب حين نكون نحن **المُرسِل**
(كالـwebhooks الصادرة، فنحمل سرّنا نحن). أمّا هنا فالشريك هو المُنادي،
وHMAC بسرٍّ مشترك يفرض أن **نحفظ سرّه قابلاً للاسترجاع** — فتسرُّبُ
قاعدتنا يُمكّن من انتحال كلّ شريك.

والسرّ الحامل فوق TLS يُعرّض السرّ للسلك وحده (وهو مُعمّى)، ويُخزَّن
عندنا مُجزَّأً بـ`scrypt` وملحٍ لكل عميل فلا يُستردّ. والمقايضة في صالح
الشركاء. ويبقى ختمُ الوقت شرطاً لسدّ إعادة الإرسال.
