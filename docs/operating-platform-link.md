## ٣. المصادقة (Auth)

- **سرّ حامل لا HMAC**: ترويسات `X-Api-Key` (`ck_live_…`)، `X-Api-Secret` (`sk_live_…`)،
  `X-Api-Timestamp` (ثوانٍ أو مللي ثانية، نافذة ٣٠٠ ثانية). السرّ مخزَّن مُجزَّأً بـscrypt وملح،
  ولا يُسترجع (`src/lib/integrations/auth.ts:19-47`, `:94-101`؛ `src/lib/integrations/client.ts:46-72`).
  الترويسات القديمة `X-IOSO-*` مقبولة (`client.ts:40-44`).
- **كل فشل مصادقة يُعيد `invalid_credentials` نفسه** (مفتاح غير موجود، سرّ خاطئ، مفتاح مُبطَل) — `client.ts:66-69`.
- **المفتاح مربوط بمنصّة واحدة**: مفتاح `mirror:write` بلا `source` مرفوض بقيد
  (`ck_mirror_needs_source`، `20260919100000_mirror_sync.sql:21-23`)، و`mirror_apply` يكتب لمصدر المفتاح
  وحده (`:41-45`). مُثبت باختبار: `supabase/tests/operating-link-verification.sql` (الفحص ٤).
- **الإصدار**: مدير كهاتين وحده، ويُدوَّن في سجلّ التدقيق (`create_api_client`،
  `20260919100000_mirror_sync.sql:238-258`). الواجهة: `src/components/integrations/ApiClientsAdmin.tsx`.
- **حدود المعدّل**: بالعنوان قبل المصادقة، وبالمفتاح بعدها (٣٠٠ طلب/دقيقة لكل مفتاح) —
  `client.ts:186-197`، `src/lib/rate-limit.ts:27`.
- **حجم الجسم**: ٢ ميغابايت (`client.ts:165-180`).
- **[ملاحظة أمنية]** السرّ يسافر في كل طلب. من التقط طلباً واحداً بعد فكّ TLS يملك السرّ نفسه، فحارس
  الإعادة لا يحمي من ذلك؛ الحماية هي TLS وتدوير المفتاح. تدوير كل ٩٠ يوماً مذكور في الوثائق
  ولا يفرضه الكود. **[مقترح]** توقيع الدفعة بمفتاح خاصّ عند منصّة التشغيل (Ed25519) بدل السرّ الحامل.

## ٤. دفعة المرآة (Payload)

```http
POST /api/integrations/mirror
X-Api-Key: ck_live_…
X-Api-Secret: sk_live_…
X-Api-Timestamp: 1793000000
X-Api-Nonce: <اختياري: معرّف فريد لكل محاولة، حتى 200 حرف>
Content-Type: application/json
```

```json
{
  "entity": "students",
  "records": [{ "external_ref": "…" }],
  "deleted": ["external_ref"],
  "cursor": { "at": "2026-11-01T08:00:00Z", "ref": "آخر معرّف في الدفعة" }
}
```

أو مطابقة: `{ "entity": "students", "reconcile": ["ref1", "ref2"] }`.

الحدود: ٥٠٠ سجلّ و٥٠٠ محذوف للدفعة، ٢٠٬٠٠٠ معرّف للمطابقة (`mirror.ts:45-46`).
ترتيب الجولة إلزامي عملياً: `groups` ← `students` ← `trait_dimensions` ← `traits` ← `trait_scores`
(كلٌّ يحلّ مراجعه ممّا قبله؛ المرجع غير المحلول يُتخطّى ويُذكر في `skipped`).

### الحقول، حقلاً حقلاً (من `mirror_apply`، `20260919100000_mirror_sync.sql:33-170`)

**`groups`** → `mirror_groups`، المفتاح `(source, external_ref)`

| الحقل                                 | النوع       | المعنى                                         |
| ------------------------------------- | ----------- | ---------------------------------------------- |
| `external_ref`                        | نصّ، إلزامي | معرّف المجموعة/الصفّ في منصّة التشغيل          |
| `name`                                | نصّ         | اسم المجموعة (الافتراضي «مجموعة»)              |
| `region`                              | نصّ         | المنطقة                                        |
| `institution_ref`, `institution_name` | نصّ         | المؤسسة/المدرسة                                |
| `supervisor_ref`, `supervisor_name`   | نصّ         | المشرف الأساسي (يظهر للداعم صاحب نطاق `group`) |
| `updated_at`                          | ISO 8601    | وقت آخر تعديل في المصدر                        |

الدولة لا تُرسَل: تؤخذ من منصّة المفتاح (`_p.country_code`).

**`students`** → `orphans`، المفتاح `(external_source, external_ref)` (فريد:
`supabase/migrations/20260823063344_…sql:137`)

| الحقل             | النوع              | المعنى                                                                                    |
| ----------------- | ------------------ | ----------------------------------------------------------------------------------------- |
| `external_ref`    | نصّ، إلزامي        | معرّف الطالب في منصّة التشغيل                                                             |
| `display_name`    | نصّ، إلزامي للجديد | **اسم مستعار لا الاسم الحقيقي**                                                           |
| `gender`          | `female` أو غيره   | غير `female` يُسجَّل `male`                                                               |
| `age`             | عدد صحيح 0–40      | يُحوَّل إلى أول يناير من سنة الميلاد التقريبية؛ يُعرض فئةً عمرية فقط. **عند الإنشاء فقط** |
| `group_ref`       | نصّ                | `external_ref` لمجموعةٍ وصلت قبله                                                         |
| `region`          | نصّ                | المنطقة                                                                                   |
| `education_stage` | نصّ                | المرحلة الدراسية (نصّ حرّ؛ **ليس** مستوى التأهيل)                                         |

الطالب الجديد يُنشأ `under_review`، `monthly_need = 0`، `currency = 'EUR'` (ثابتة في الكود، `:82-89`)،
تحت جهة المنصّة (`operating_platforms.org_id`؛ غيابها يُعيد `platform_org_missing`). التحديث يمسّ
الاسم والمنطقة والمرحلة والمجموعة فقط (`:91-97`): الجنس والعمر لا يُحدَّثان بعد الإنشاء.

**`trait_dimensions`** → `trait_dimensions`، المفتاح `(source, key)`:
`key` (أو `external_ref`)، `label_ar` (أو `key`)، `label_local`, `description`, `sort_order`.

**`traits`** → `trait_definitions`، المفتاح `(source, external_ref)`:
`external_ref`, `dimension_key` (إلزامي، وإلا `unknown_dimension`)، `name_ar`, `name_local`,

**`trait_scores`** → `orphan_trait_scores`، المفتاح `(source, external_ref)`

| الحقل          | النوع                   | المعنى                                            |
| -------------- | ----------------------- | ------------------------------------------------- |
| `external_ref` | نصّ، إلزامي             | معرّف التقييم                                     |
| `student_ref`  | نصّ                     | طالبٌ وصل قبله                                    |
| `trait_ref`    | نصّ                     | سمةٌ وصلت قبله                                    |
| `score`        | عدد ≥ 0 و≤ `scale_max`  | الدرجة كما هي                                     |

### الفحص قبل القاعدة (أُضيف في هذه الجولة)

`src/routes/api/integrations/-mirror-payload.ts`: قيمةٌ لا تُقرأ (عمر غير صحيح، تاريخ غير ISO،
درجة فوق سقفها، سجلّ ليس كائناً…) تُردّ `422 invalid_record` مع
`issues: [{ index, ref, field, reason }]` (حتى ٢٠)، ولا يُطبَّق من الدفعة شيء. قبل ذلك كانت تُسقط
الدفعة بـ`500 apply_failed` بلا تحديد (مُثبت على قاعدة محلية).

### الردّ

```json
{
  "ok": true,
  "applied": 12,
  "deleted": 0,
  "skipped": [{ "ref": "…", "reason": "unresolved_reference" }],
  "receipt": { "payload_hash": "<sha256>", "chain_hash": "<sha256>" }
}
```

`payload_hash` بصمة المحتوى المعياري للدفعة، و`chain_hash` حلقتها في سلسلة دفعات المصدر
(`mirror.ts:174-189`، `mirror_log_batch` في `20260922100000_integrity.sql:590-605`). على المُرسِل حفظهما.

## ٦. الاتجاه والتواتر (Sync direction & frequency)

- **اتجاه واحد**: منصّة التشغيل تدفع (push)، وكهاتين لا تسحب ولا تكتب هناك
  (`20260919100000_mirror_sync.sql:4-7`). لا يوجد في هذا المستودع نداء صادر إلى `base_url`.
- **التواتر**: لا يفرضه الكود. المرجع الوحيد: تنبيه `mirror_lag` لمنصّة `active` بلا دفعة منذ ٤٨ ساعة
  (`supabase/migrations/20260926100000_ops_health.sql:84-91`)، والمطابقة «مرّة يومياً» في
  `docs/rowad-sync.ar.md`. **[مقترح]** دفعات تزايدية كل ساعة على الأكثر، ومطابقة كاملة يومية.
- **المؤشّر**: `cursor.at`/`cursor.ref` يُحفظان لكل (مصدر، كيان) في `mirror_sync_state` ولا يُعادان في
  ردّ؛ المُرسِل يحفظ مؤشّره بنفسه. **[مقترح]** `GET` يعيد آخر مؤشّر محفوظ ليستأنف المُرسِل بعد فقد حالته.

## ٧. التكرار والإعادة والتعارض (Idempotency, replay, conflict)

| الحالة                                          | ما يحدث                                                                                              | المرجع / الإثبات                                         |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| الدفعة نفسها تُرسَل ثانيةً بختم جديد            | تُحدِّث بالمفتاح `(source, external_ref)` ولا تُضاعف؛ تُسجَّل حلقة جديدة في السلسلة                  | `operating-link-verification.sql` (١، ٢)                 |
| الطلب نفسه حرفاً بحرف (الختم نفسه) داخل النافذة | `409 replay_detected`                                                                                | `client.ts:111-162`، `auth.ts:73-89`                     |
| ترويسة `Idempotency-Key` على بوّابة المرآة      | **تُتجاهل** (المرآة لا تحجز مفاتيح تكرار). كانت تُسقط حارس الإعادة؛ أُصلح في هذه الجولة              | `-mirror-payload.ts` (`withoutIdempotencyKey`)، واختباره |
| `Idempotency-Key` على بوّابة الاستيراد          | حجز ذرّي: النتيجة الأولى تُعاد، أو `idempotency_in_progress`، أو `idempotency_key_reused`            | `orphans.ts:172-220`                                     |

## ٨. الأقفال والإذن الموقّع (Locks & signed grant)

- القفل يقع عند أول كفالة فعّالة أو دعم مقبول أو صرف (`integrity.sql:146-175`).
- الفكّ: طلب بسبب ومستند، موافقة مسؤولَين، نافذة ١٥ دقيقة (`integrity.sql:199-340`).
- لعمليةٍ في منصّة التشغيل (`rowad_update`/`rowad_delete`): `admin_grant_payload` يبني الحمولة
  (`iss, aud="rowad:<CC>", sub="students/<ref>", op, fields, request_id, approved_by, exp, jti`) والخادم يوقّعها
  JWS/EdDSA بمفتاح `GRANT_SIGNING_KEY` (`src/lib/integrity/grant.ts`، `src/lib/integrity.functions.ts:289-311`).
- **الإذن يُعرض للمدير لينقله يدوياً**؛ لا يوجد نداء إلى منصّة التشغيل. التحقّق ومنع إعادة `jti`
  مسؤولية منصّة التشغيل (`grant.ts:55-58`). `aud` مثبَّت على البادئة `rowad:`.

## ٩. الخصوصية (ما لا يغادر الحاجب)

1. الاسم الحقيقي لا يدخل أصلاً: العقد يطلب اسماً مستعاراً. **لا يملك الكود وسيلة للتحقّق من ذلك.**
2. تاريخ الميلاد لا يُرسَل؛ العمر يصير فئة عمرية.
3. ملاحظة المشرف (`note`) لا تخرج من أيّ دالّة قراءة للداعم.
4. الصورة والمكان الدقيق: ليسا في المرآة، وفي القراءة خلف حاجب الأطفال (AGENTS.md «Protected reads»).
5. مفتاح الشريك ليس إذناً برؤية ملفّ: `GET` يعيد البطاقة فقط (`orphans.ts:22-26`).
6. المستورَد والمرآوي لا يُنشر: يقف `under_review` والحارس في القاعدة.
7. جداول المرآة مغلقة على غير المدير؛ القراءة بدوالّ تفحص النطاق.
8. `public_operating_links()` مجاميع بلا اسم ولا معرّف (مُثبت: الفحص ٧).
9. المال لا يذهب إلى منصّة التشغيل في أيّ مسار.
