# الدفع عبر Creem — الحالة وما هو مطلوب منك

> **تصحيح جوهري:** المزوّد **Creem** (creem.io) وليس **Careem** (كريم للتوصيل).
> شركتان مختلفتان تماماً بواجهتين لا تشبه إحداهما الأخرى. بُني الربط أولاً على
> الافتراض الخاطئ، وأُعيد بناؤه بالكامل على المواصفة الحقيقية.

## 1. مصدر المواصفة

وثائق Creem محجوبة عن هذه البيئة، فأُخذت المواصفة من **حزمة `creem` الرسمية على
npm (الإصدار 1.6.0)**: تعريفات الأنواع فيها مولَّدة من مواصفة OpenAPI الخاصة
بالمزوّد، فهي أدقّ ما يُتاح خارج الوثائق نفسها — وأدقّ من أمثلة مكتوبة بخطّ اليد.

| البند            | القيمة المؤكَّدة                         |
| ---------------- | ---------------------------------------- |
| نطاق الإنتاج     | `https://api.creem.io`                   |
| نطاق الاختبار    | `https://test-api.creem.io`              |
| المصادقة         | ترويسة `x-api-key` (لا OAuth ولا Bearer) |
| إنشاء جلسة دفع   | `POST /v1/checkouts`                     |
| إلغاء اشتراك     | `POST /v1/subscriptions/{id}/cancel`     |
| إنشاء منتج       | `POST /v1/products`                      |
| ترويسة التوقيع   | `creem-signature`                        |
| خوارزمية التوقيع | HMAC-SHA256 على الجسم الخام، بترميز hex  |
| العملات المدعومة | **USD** و EUR فقط                        |
| غلاف الحدث       | `{ id, eventType, created_at, object }`  |

> `eventType` بالسنام لا `event_type`، بخلاف بقيّة الحقول. مثبَّت في أنواع الحزمة.

## 2. القيد الذي شكّل التصميم كلّه

الدفع لدى Creem مربوط بـ**منتج** لا بمبلغ حرّ: لا تقول «حصّل 80 دولاراً» بل
«حصّل المنتج X بعدد Y وحدة».

والحقل الوحيد الذي يقبل مبلغاً حرّاً — `custom_price` — نصّ المزوّد عليه:

> «Only supported for one-time payment products.»

والكفالة **شهرية متكرّرة بمبلغ يختاره الكافل**، فهي تقع في التقاطع الذي لا
يغطّيه `custom_price`. الحلّ المعتمد:

| الحالة      | كيف تُنفَّذ                                                                         |
| ----------- | ----------------------------------------------------------------------------------- |
| كفالة شهرية | منتج متكرّر سعر وحدته **دولار واحد شهرياً**، و`units` = المبلغ. كفالة 80$ = 80 وحدة |
| دفعة واحدة  | منتج دفعة واحدة + `custom_price` بالسنتات (يقبل الكسور)                             |

والوحدات تضرب السعر — موثَّق في وصف `custom_price` نفسه: «the amount is per unit:
with `units: 3` and `custom_price: 1500` the customer pays 4500».

**الأثر العملي:** مبالغ الكفالة الشهرية بالدولار الصحيح. 80$ نعم، 80.50$ تُدوَّر.
هذا مقبول لأن واجهة الكفالة تتعامل بأعداد صحيحة أصلاً.

## 3. ⚠️ خطر يجب حسمه قبل أي إطلاق

سياسة الاستخدام المقبول لدى Creem تمنع صراحةً:

> «donations or charity giving where no product exists or where the price is
> greater than the product value»

ومنصّة كفالة أيتام هي **تبرّع خيري بلا منتج** بالتعريف. وCreem يعمل بنموذج
Merchant of Record ويصرّح أنه موجَّه للمنتجات الرقمية — SaaS وأدوات وقوالب.

الخطر ليس رفض التسجيل، بل **تعليق الحساب بعد التشغيل وتجميد الأموال**: أموال
كفلاء محتجزة وأيتام بلا صرف. هذا أسوأ من عدم الإطلاق أصلاً.

**المطلوب منك قبل أي دفعة حقيقية:** موافقة **مكتوبة** من Creem على حالة الاستخدام
موصوفةً كما هي — «منصّة كفالة أيتام، اشتراك شهري متكرّر، تحويل الأموال إلى جهات
رعاية». احتفظ بالردّ. إن رُفض، فالبدائل التي تخدم الجمعيات صراحةً أنسب.

الكود جاهز للحالتين: المحوّل معزول، وتبديل المزوّد لا يمسّ مساراً ولا جدولاً ولا
شاشة — وهذا ما أثبته انتقالنا من Careem إلى Creem فعلاً.

## 4. ما أحتاجه منك بالضبط

أربع قيم. **لا تكتب أياً منها هنا في المحادثة ولا في `.env`** — الملف متتبَّع في
Git، وما يدخله يبقى في التاريخ حتى بعد حذفه.

| المتغيّر                | من أين تأخذه                               | ملاحظة                              |
| ----------------------- | ------------------------------------------ | ----------------------------------- |
| `CREEM_API_KEY`         | لوحة Creem ← Developers ← API Keys         | ابدأ بمفتاح الاختبار `creem_test_…` |
| `CREEM_WEBHOOK_SECRET`  | لوحة Creem ← Webhooks ← عند إنشاء الويبهوك | **يُعرض مرّة واحدة**                |
| `CREEM_PRODUCT_MONTHLY` | معرّف المنتج المتكرّر (خطوة ٥)             | `prod_…`                            |
| `CREEM_PRODUCT_ONETIME` | معرّف منتج الدفعة الواحدة (خطوة ٥)         | `prod_…` — اختياري                  |

وللتفعيل: `PAYMENT_PROVIDER=creem`.

**أين تضعها:** في **Lovable Cloud ← Environment Variables** (أو `.env.local` محلياً
وهو مستثنى من Git). ضعها هناك وأخبرني «تمّ» فقط — لا تنسخ القيم إليّ.

البيئة تُشتقّ من المفتاح تلقائياً: `creem_test_` ⇒ نطاق الاختبار، وغيره ⇒ الإنتاج.
فلا يوجد متغيّر بيئة منفصل يمكن أن يتناقض مع المفتاح.

## 5. المنتجان اللذان تُنشئهما في لوحة Creem

**الأول — إلزامي:**

| الحقل          | القيمة           |
| -------------- | ---------------- |
| Name           | وحدة كفالة شهرية |
| Price          | **1.00 USD**     |
| Billing type   | Recurring        |
| Billing period | Every month      |

السعر دولار واحد **مقصود**: هو وحدة القياس لا سعر الكفالة. المبلغ الحقيقي يأتي
من `units`.

**الثاني — اختياري** (للدفعة الواحدة): نفس الاسم بصيغة «دفعة كفالة»، `Price` أي
قيمة (تُتجاوَز بـ`custom_price`)، و`Billing type: One-time`.

## 6. الويبهوك

- **Endpoint URL:** `https://<نطاقك>/api/payments/webhook`
- **الأحداث:** الثلاثة عشر كلّها كما في لقطتك — المعالج يتعامل معها جميعاً.

| حدث Creem                                                    | ما يفعله النظام                                    |
| ------------------------------------------------------------ | -------------------------------------------------- |
| `checkout.completed`                                         | يسجّل الدفعة ويُفعّل الكفالة                       |
| `subscription.paid`                                          | يسجّل دفعة التجديد الشهري                          |
| `subscription.canceled` / `expired`                          | ينهي الكفالة                                       |
| `subscription.unpaid` / `past_due`                           | يسجّل فشل دفعة ولا يلغي الكفالة                    |
| `subscription.paused`                                        | يوقف الكفالة مؤقتاً                                |
| `refund.created`                                             | يَسِم الدفعة مردودة                                |
| `dispute.created`                                            | يَسِم الدفعة **متنازعاً عليها** ويُخرجها من الرصيد |
| البقيّة (`active`، `trialing`، `update`، `scheduled_cancel`) | تُسجَّل ويُعتمَد استلامها بلا فعل                  |

الفئة الأخيرة مقصودة: رفض حدث لا فعل له يجعل Creem يعيد إرساله بلا نهاية.

والمنازعة مفصولة عن ردّ المبلغ عمداً: الردّ قرار من التاجر، والمنازعة نزاع
يفتحه حامل البطاقة وقد يُحسم لأيّ طرف. خلطهما يُخفي مالاً معلّقاً عن اللوحة.

## 7. حال الربط الآن

| العنصر                                  | الحالة                                       |
| --------------------------------------- | -------------------------------------------- |
| المحوّل الكامل بالمواصفة الحقيقية       | ✅ `src/lib/payments/creem.ts`               |
| التحقّق من التوقيع (مقارنة ثابتة الزمن) | ✅ مغطّى بأربعة اختبارات                     |
| منع تكرار الأحداث                       | ✅ قيد تفرّد `(provider, provider_event_id)` |
| تفسير الأحداث الثلاثة عشر               | ✅ مغطّى باختبارات                           |
| المنازعة في القاعدة واللوحة             | ✅ هجرة + ثلاثة فحوص                         |
| الرجوع للتحويل اليدوي عند نقص الأسرار   | ✅ لا صفحة دفع مكسورة                        |
| **موافقة Creek على حالة الاستخدام**     | ⏳ **عليك**                                  |
| القيم الأربع في متغيّرات البيئة         | ⏳ **عليك**                                  |

بعد وضع القيم لا يحتاج الكود تعديلاً: `paymentProvider()` يلتقط الإعداد ويعمل.

## 8. الاختبار قبل الإنتاج

1. ضع مفتاح الاختبار `creem_test_…` (يستعمل نطاق الاختبار تلقائياً).
2. أنشئ كفالة من الواجهة → يجب أن تُفتح صفحة دفع Creem.
3. أتمم الدفع ببطاقة الاختبار.
4. تحقّق أن الكفالة صارت `active` وأن `sponsorship_payments` فيها صفّ `paid`.
5. أعِد إرسال الحدث نفسه من لوحة Creem → يجب أن يُردّ `200` بلا صفّ مكرّر.
6. جرّب الإلغاء → يجب أن تصير الكفالة `cancelled`.

الخطوة الخامسة هي الأهمّ: البوابات تُعيد الإرسال عند أي شكّ في التسليم، وبلا
منع التكرار يُحصَّل الكافل مرّتين على الورق.
