# وضع التجربة — كيف يعمل، وكيف يُحذف بأمرٍ واحد يوم الإطلاق

## ما هو

وضع التجربة (`/try`) رحلةٌ كاملة بلا حساب ولا خصم: أطفالٌ افتراضيون بأسماءٍ مستعارة، ودفعٌ
محاكى، وأدوار الإدارة والمكتب والمشرف وصاحب القرار، وقاعة الأثر على كتالوج التجربة. كلّه في
متصفّح الزائر، ولا يصل الخادم.

ملفّاته كلّها مسرودة في **`trial.manifest.json`** (الحقل `files`):

| النمط                                        | ما فيه                                                                 |
| -------------------------------------------- | ---------------------------------------------------------------------- |
| `src/routes/try.tsx`، `src/routes/try.*.tsx` | مسارات التجربة                                                         |
| `src/lib/try-*.ts`                           | كتالوجها ومخازنها ونسخها التجريبية من العمليات، ومدخلها `try-entry.ts` |
| `src/lib/hall/trial*.ts`                     | كتالوج قاعة التجربة واختباراته                                         |
| `src/components/try/**`                      | مكوّناتها                                                              |
| `scripts/gen-try-world.mjs`                  | مولّد مناطقها                                                          |

واختبارات التجربة تعيش معها (`try-*.test.ts`، `hall/trial-*.test.ts`)، فتُحذف معها.

## القاعدة: الكود الحقيقي لا يستورد ملفّ تجربة أبداً

ثلاثة مواضع حقيقية وحدها تعرف التجربة، وكلّها تبقى بعد حذفها:

1. **`src/lib/trial-gate.ts`** — `TRIAL_ENABLED`: صحيحٌ ما دام مدخل التجربة
   (`src/lib/try-entry.ts`) موجوداً. يُسأل عنه بـ`import.meta.glob` فلا يُستورد. ومنه
   `trialRoute("/try/…")`: رابطٌ إلى التجربة بنوعٍ لا يحتاج مسارات `/try`، فيبقى الكود يُبنى
   بعد زوالها. كلّ رابطٍ إلى `/try` في الكود الحقيقي يمرّ منه، وفي فرعٍ لا يُبلغ إلا والتجربة
   موجودة (`TRIAL_ENABLED`، أو جلسة العرض `useDemo()` التي تصير كاذبة دائماً بلا تجربة).
2. **`src/lib/trial-slots.ts`** — قطع التجربة التي تعرضها شاشاتٌ حقيقية، بالاسم:
   `trialSlots?.ProposalOffer` (ملفّ الطفل وبطاقة المكان)، `ProposalCard` (لوحة الداعم)،
   `AuthNotice` (الدخول)، `dismissProposal`، و`loadSupportMap` و`loadDirectory`
   و`loadAdminOverlay` و`loadHall` (تُحمَّل عند الطلب). العقود (أنواع الخصائص) مكتوبة هنا،
   والمدخل يلتزم بها (`satisfies TrialSlots`). بلا تجربة: `trialSlots` فارغ (`null`)، فلا يُعرض
   شيء.
3. **`src/lib/data-port.ts`** — بيانات الشاشات: `useDataFn("مجال.عملية", دالة_الخادم)`. في جلسة
   العرض تُنادى النسخة التي سجّلتها التجربة بـ`registerDemo`، وإلا الخادم.

وقاعة الأثر (`src/lib/hall/source.ts`): بلا تجربة، ما كان يفتح قاعة التجربة (`/hall` و`?try=1`)
يفتح القاعة الحيّة، وتبقى قاعة الداعم (`?me=1`) كما هي.

الأقفال:

- `src/lib/trial-manifest.test.ts`: لا ملفّ خارج البيان يستورد ملفّاً منه (`from` و`import()`
  و`vi.mock`)، والبوّابة والفتحات تسألان عن ملفٍّ من البيان.
- `src/lib/data-port.test.ts`: كلّ عمليةٍ في شاشةٍ حقيقية لها نسخةٌ تجريبية (ما دامت التجربة).
- `src/lib/demo-real-boundary.test.ts`: البوّابات بعد الدخول ودوال الخادم لا تمسّ وحدة تجربة.
- مهمّة CI **«حذف التجربة بأمرٍ واحد»**: تحذفها فعلاً في نسخةٍ مؤقّتة ثم تفحص الأنواع والاختبارات
  والبناء. يفشل الطلب إن صارت التجربة لا تُحذف.

## ميزةٌ جديدة: الترتيب

1. **الشاشة الحقيقية أوّلاً**، ببياناتها من الخادم عبر المنفذ:
   `const fn = useDataFn("مجال.عملية", serverFn)`، ومفتاح الاستعلام `useDataKey([...])`.
2. **النسخة التجريبية في ملفّ تجربة** (`src/lib/try-….ts`):
   `registerDemo("مجال.عملية", async (input) => …)` بالاسم نفسه. `data-port.test.ts` يفشل إن
   نُسيت.
3. إن احتاجت الشاشة **قطعة واجهة** من التجربة: أضف خانتها وعقدها في `src/lib/trial-slots.ts`،
   وقيمتها في `src/lib/try-entry.ts`، واعرضها في الشاشة بـ`{Slot && <Slot … />}`. لا استيراد.
4. **رابطٌ إلى التجربة**: `trialRoute("/try/…")` داخل `TRIAL_ENABLED` أو `useDemo()`.
5. ملفٌّ جديد للتجربة خارج الأنماط؟ أضفه إلى `trial.manifest.json`.
6. اختبار يقرأ ملفّات التجربة أو يستوردها: ضعه بين ملفّاتها (`try-*.test.ts` أو
   `hall/trial-*.test.ts`).

## يوم الإطلاق

### الأمر

```sh
npm run trial:remove              # تشغيلٌ جافّ: يسرد الملفّات والإعداد، ولا يمسّ شيئاً
npm run trial:remove -- --apply   # الحذف
```

### ما يفعله `--apply`

1. يحذف كلّ ملفٍّ في `trial.manifest.json` والمجلّدات التي تفرغ (`src/components/try`).
2. يضبط `src/config/platform.ts`: `PLATFORM_MODE = "live"` و`KEEP_TRIAL_PUBLIC = false`؛ فتقود
   «اكفل يتيماً» والصفحة الأولى إلى الدليل الحقيقي.
3. يعيد فهرس النصوص (`node scripts/i18n-extract.mjs`)، فتسقط نصوص التجربة من
   `src/i18n/catalog.json`.
4. يعيد توليد شجرة المسارات بـ`npx vite build` (`src/routeTree.gen.ts` بلا `/try`). (`--no-build`
   يتخطّاه لمن يبني بنفسه بعده.)

لا يُعدَّل سطرٌ في الكود الحقيقي: البوّابة ترى غياب المدخل، فتختفي روابط التجربة وشريط العرض
وفروع جلسة العرض وحدها. ولا شيء في قاعدة البيانات يخصّ التجربة.

### التحقّق

```sh
npx tsc --noEmit && npx vitest run && npx vite build
git status            # ملفّات التجربة محذوفة، وplatform.ts وcatalog.json وrouteTree.gen.ts معدّلة
```

ثم في المتصفّح: `/` بلا زرّ «ادخل التجربة»، و`/try` صفحة «غير موجود»، و`/hall` القاعة الحيّة،
و`/support` و`/orphans` الحقيقيّتان.

### الالتزام والتراجع

التزم بالحذف في التزامٍ واحد وادفعه إلى الفرع المتّصل بـLovable. للتراجع: `git revert <الالتزام>`
ثم ادفع — التزامٌ جديد يعيد الملفّات كما كانت. **لا** `reset` ولا دفع بالقوّة: ذلك يعيد كتابة
تاريخٍ يملكه Lovable (AGENTS.md).
